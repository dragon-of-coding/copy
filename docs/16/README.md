## Вопрос 1. Процессы приобретения и поставки программных средств. Критерии приёмки продукта

Приобретение — процесс заказчика: определение потребности, формулирование требований, выбор поставщика, заключение соглашения, контроль выполнения и приёмка результата. Поставка — процесс исполнителя: анализ требований договора, планирование работ, разработка или подготовка продукта, предоставление, поддержка испытаний и передача результатов. Они взаимосвязаны через соглашение, сроки, объём и критерии качества.

Сначала формируют понятные проверяемые требования. Далее согласуют ответственность сторон, состав поставки, сроки, порядок изменения объёма и способ разрешения спорных ситуаций. Исполнитель формирует продукт и доказательства соответствия, заказчик проверяет документацию, функциональность, совместимость, безопасность и результаты испытаний.

Критерии приёмки — заранее согласованные, измеримые условия, при выполнении которых продукт считается принятым. Примеры: все обязательные сценарии пройдены; критических дефектов нет; сервис отвечает за установленное время; программа устанавливается по инструкции на указанную ОС; БД сохраняет данные после перезапуска; присутствует комплект документации. Важно заранее определить степень допустимых некритичных дефектов.

Приобретение означает получение ПО заказчиком: выбор решения, согласование требований, договора, цены, сроков и процедуры приёмки. Поставка — обязанности исполнителя по созданию или передаче согласованного продукта, документации и результатов проверок. Критерии приёмки желательно сделать измеримыми: например, сервис запускается на указанной ОС, выполняет заданные операции, корректно отказывает при неверном вводе и передаётся с инструкцией. Приёмка отличается от внутреннего тестирования: заказчик проверяет, что получил именно нужный ему результат. Если обнаружено несоответствие, его оформляют с указанием ожидаемого поведения, а исправление проверяют до подписания результата.

Итоговые документы: протокол тестирования, перечень замечаний, акт приёмки, сведения о версии. Вывод: приёмка должна быть основана на требованиях и проверяемых критериях, а не на субъективном впечатлении «вроде работает».

## Вопрос 2. Причины конфликтов слияния в Git и порядок их разрешения

Конфликт слияния возникает, когда Git не может автоматически совместить изменения, например две ветки по-разному изменили одни и те же строки или одна ветка удалила файл, который другая отредактировала. Не всякое изменение одного файла создаёт конфликт: разные непересекающиеся участки Git часто объединяет сам.

При конфликте выполняют git status, открывают отмеченные файлы и находят маркеры <<<<<<<, =======, >>>>>>>, разделяющие конкурирующие варианты. Нужно понять смысл обеих правок, вручную составить правильный итоговый код, удалить маркеры, запустить тесты. После этого git add <файл> отмечает разрешение. При merge завершают коммит слияния; при rebase обычно выполняют git rebase --continue. Для отмены начатой операции есть git merge --abort или git rebase --abort.

Профилактика: небольшие изменения, частая синхронизация веток, согласование интерфейсов модулей, код-ревью и автоматические тесты. Опасная ошибка — без анализа выбирать целиком «ours» или «theirs», теряя нужную функциональность.

Конфликт Git возникает, когда система не может автоматически объединить изменения — например, две ветки по-разному исправили одну строку или одна удаляет файл, который другая изменяет. Git отмечает конфликтные участки специальными маркерами. Разработчик открывает файл, изучает обе версии, выбирает корректное итоговое содержимое и удаляет маркеры. После этого он запускает тесты, отмечает разрешённые файлы через git add и завершает слияние коммитом либо командой git merge --continue. При необходимости слияние можно отменить через git merge --abort, если оно ещё не завершено. Нельзя просто убрать маркеры, не проверив смысл кода.

Вывод: разрешить конфликт — значит объединить смысл изменений и проверить итоговое поведение программы.

## Практическое задание. Расчёт цены со скидкой

Условие (по скану преподавателя). A1 — кеды — 2500 руб. — скидка 10%; A2 — ботинки — 4800 руб. — 20%; A3 — сандалии — 1900 руб. — 0%. По артикулу рассчитать цену по формуле цена × (100 − скидка) / 100; вывести название, исходную и итоговую цену с двумя знаками. Неизвестный товар — «Товар не найден».

### Решение на Python 3

[Открыть код](practice.py). Запуск из корня проекта

```sh
python docs/16/practice.py
```

### Как объяснить код преподавателю

Словарь связывает артикул с названием, исходной ценой и скидкой. Вычисляем сумму после скидки по указанной формуле; format(..., '.2f') нужен, чтобы показать два знака, включая нули.

Важно: это самостоятельная консольная программа; исходные данные хранятся в памяти во время запуска. Для данного билета не нужно создавать базу данных и интерфейс.

### Проверь себя

Ввод: A1   →   Ожидается: 2500.00 и 2250.00 руб.

Ввод: A3   →   Ожидается: 1900.00 и 1900.00 руб.
