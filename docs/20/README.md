## Вопрос 1. Графические ускорители, операционная система и драйверы в составе платформы

Графический ускоритель (GPU) выполняет массово параллельные вычисления и обработку графики. Он применяется для визуализации, 3D, видеокодирования, машинного обучения и некоторых научных задач. Важны производительность вычислительных блоков, объём и пропускная способность видеопамяти, поддерживаемые API (например Vulkan, DirectX, OpenGL, CUDA) и совместимость драйвера.

Операционная система управляет памятью, процессами, файлами, устройствами, правами доступа и сетью, предоставляя приложениям системные интерфейсы. Драйвер — программный компонент, обеспечивающий взаимодействие ОС с конкретным устройством. Даже подходящая видеокарта может не поддерживать отдельную функцию без требуемой версии драйвера и библиотек.

При выборе платформы оценивают требования ПО к GPU и CPU, архитектуре, ОС, драйверам, API, объёму памяти и охлаждению. Обновления драйверов иногда улучшают производительность и исправляют ошибки, но могут изменить совместимость; их тестируют на целевом наборе программ. Для сервера без графических задач дискретный ускоритель может быть не нужен.

Графический ускоритель предназначен для массово-параллельных вычислений и вывода графики, но его возможности зависят от драйвера и программного интерфейса. Для приложений могут быть важны версии DirectX, Vulkan, OpenGL, CUDA или других сред. Операционная система управляет устройствами и распределяет ресурсы, драйвер обеспечивает взаимодействие с конкретным оборудованием. При выборе платформы проверяют не только название видеокарты, но и поддержку нужной функциональности, память, энергопотребление, драйверы и совместимость библиотек. Для серверного приложения без графической нагрузки мощный GPU может вовсе не требоваться, а критичнее окажутся RAM и диск.

Вывод: GPU даёт аппаратные возможности, ОС предоставляет среду выполнения, а драйвер соединяет программные запросы с устройством.

## Вопрос 2. Интеграционное тестирование файловых операций. Изоляция данных через TemporaryDirectory

Интеграционное тестирование проверяет совместную работу нескольких компонентов: функции приложения, файловой системы, кодирования, сериализации и обработки ошибок. В отличие от чистого модульного теста, оно использует настоящий ресурс, например временный файл. Это выявляет ошибки путей, закрытия файлов, форматов и прав.

tempfile.TemporaryDirectory() создаёт уникальный временный каталог и автоматически удаляет его после выхода из блока with. Пример: with TemporaryDirectory() as d: path = Path(d) / "data.json"; save(path, data); result = load(path); assert result == data. Использование собственного каталога для каждого теста исключает пересечение результатов и риск испортить реальные данные пользователя.

Проверяют обычное сохранение и чтение, отсутствие файла, неверный формат, пустой документ, кодировку UTF-8, повторную запись и поведение при ошибках. В unittest можно создавать временный каталог в setUp с последующей уборкой или непосредственно в тесте. Проверки файлов не должны зависеть от текущего рабочего каталога и файлов, оставленных предыдущими тестами.

Интеграционный тест проверяет работу нескольких компонентов вместе, например запись файла, чтение его содержимого и последующее удаление. Такие тесты могут случайно испортить настоящие файлы, если используют постоянные пути. TemporaryDirectory из стандартной библиотеки создаёт временную папку и помогает изолировать тестовые данные; после завершения контекста она удаляется. Тест обычно создаёт исходные данные, вызывает проверяемый код, читает результат и сравнивает с ожидаемым. Нужно проверить как положительный путь, так и ситуации отсутствующего файла или неверных прав, если они предусмотрены системой. Повторный запуск теста должен давать тот же результат без ручной очистки компьютера.

Вывод: временная директория позволяет проверять реальные файловые операции воспроизводимо и безопасно.

## Практическое задание. Добавление товара с проверкой данных

Условие (по скану преподавателя). ID 1 — кеды — 2500 руб., ID 2 — ботинки — 4800 руб., ID 3 — сандалии — 1900 руб. Ввести непустое название и числовую неотрицательную цену; при успехе добавить запись с ID = максимальный существующий + 1 и показать список. При ошибке не изменять записи.

### Как объяснить код преподавателю

float() пытается превратить введённую строку в число, а try/except перехватывает неверный текст. math.isfinite() исключает бесконечность и NaN. В цикле ищем самый большой ID, затем добавляем новый товар.

Важно: это самостоятельная консольная программа; исходные данные хранятся в памяти во время запуска. Для данного билета не нужно создавать базу данных и интерфейс.
