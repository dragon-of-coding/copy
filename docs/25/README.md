## Вопрос 1. Виртуализация и контейнеризация. Требования к аппаратной и программной среде

Виртуализация позволяет на одном физическом сервере запускать несколько виртуальных машин, каждая с собственной гостевой ОС и виртуальными устройствами. Работой управляет гипервизор. Это обеспечивает сильную изоляцию сред, возможность использовать разные ОС и удобное распределение ресурсов, но требует памяти и диска на каждую ОС.

Контейнеризация изолирует процессы с помощью механизмов ОС. Контейнер включает приложение и его пользовательские зависимости, но использует ядро хоста (для Linux-контейнеров требуется Linux-ядро, непосредственно или внутри виртуальной машины). Контейнеры обычно легче и стартуют быстрее, чем полноценные ВМ. Однако изоляция контейнера не тождественна изоляции гипервизора; безопасность зависит от настроек ядра, прав и окружения.

Требования к платформе: достаточный CPU, ОЗУ и диск, поддерживаемая ОС и архитектура, виртуализация CPU для сценариев с ВМ, совместимые версии Docker/Container Runtime, сеть и порты, доступ к хранилищу, права и средства безопасности. Для GPU-нагрузок необходима совместимость драйверов и контейнерного runtime. Выбор зависит от типа приложения, нужной изоляции и операционных расходов.

Виртуальная машина эмулирует отдельный компьютер с собственной гостевой ОС, а контейнер обычно разделяет ядро ОС хоста и изолирует процессы с помощью механизмов операционной системы. ВМ удобна для разных ОС и более жёсткой изоляции, но требует больше ресурсов. Контейнер легче запускать и переносить, однако он зависит от совместимости ядра и контейнерного движка. Для обоих вариантов нужно проверить архитектуру процессора, доступную RAM, диск, сеть, виртуализацию и требования приложений. Контейнеризация не отменяет необходимость обновлений и разграничения прав. В ряде систем Docker на Windows запускает Linux-контейнеры через виртуализированную Linux-среду.

Вывод: виртуальная машина виртуализирует компьютер и ОС, контейнер — среду выполнения процесса; подходы могут использоваться совместно.

## Вопрос 2. Тестирование консольного приложения через subprocess: код возврата, stdout и stderr

Тестирование через subprocess проверяет приложение как отдельный процесс, максимально близко к реальному запуску пользователем. В отличие от вызова функции, здесь проверяются обработка аргументов, стандартный ввод, сообщения, код завершения и реакции на неправильные данные. Это полезно для CLI-программ, скриптов установки и небольших сервисных утилит.

Обычно применяют subprocess.run([...], input="...", text=True, capture_output=True, timeout=...). Поле returncode показывает код возврата: 0 по общему соглашению — успешное выполнение, ненулевое значение — ошибка. stdout содержит обычный вывод, stderr — диагностический поток. Поскольку программа сама может выводить ошибку в stdout, правило разделения потоков нужно проверять по её контракту.

Проверяют успешный сценарий, некорректный ввод, пустые данные, завершение процесса и превышение времени ожидания. Важно использовать список аргументов и shell=False по умолчанию, чтобы избежать ошибок экранирования и командной инъекции. Тест запускают в изолированном каталоге и задают тайм-аут, чтобы программа с бесконечным циклом не повесила CI.

subprocess из стандартной библиотеки Python позволяет запустить другую программу и проверить её результат как пользователь консоли. При тестировании важны код возврата (returncode), стандартный вывод stdout и поток ошибок stderr. Например, можно подать тестовую строку во вход программы, а затем убедиться, что текст ответа соответствует ожидаемому и программа завершилась с нужным кодом. Чтобы тест не завис, задают тайм-аут. Ошибки кодировки учитывают через text=True и encoding. Такая проверка полезна как интеграционный тест интерфейса консоли, но она не заменяет модульные тесты отдельных функций: при ошибке сложнее установить, в какой части программы находится причина.

Вывод: тест через subprocess показывает не только правильность расчёта, но и качество интерфейса программы как самостоятельной команды.

## Практическое задание. Просмотр карточки обувного товара

Условие (по скану преподавателя). A1 — кеды — спортивная обувь — 2500 руб.; A2 — ботинки — демисезонная обувь — 4800 руб.; A3 — сандалии — летняя обувь — 1900 руб. По артикулу показать карточку из четырёх полей, каждое на отдельной строке. Если не найден — «Товар не найден».

### Решение на Python 3

[Открыть код](practice.py). Запуск из корня проекта

```sh
python docs/25/practice.py
```

### Как объяснить код преподавателю

После нахождения артикула программа выводит его и три поля из словаря по одному. Отдельный else нужен для случая, когда такого товара нет.

Важно: это самостоятельная консольная программа; исходные данные хранятся в памяти во время запуска. Для данного билета не нужно создавать базу данных и интерфейс.
